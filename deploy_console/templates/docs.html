NOTBOOK CONSOLE — PLAIN ENGLISH GUIDE ← Back to console

This page explains the Deploy Console like you’re not a programmer. Think of two separate apps on the internet (or your computer): the Telegram bot (answers students) and this console (the control panel for books, settings, and hosting).

Big idea
The bot and the console are roommates, not the same person. Each has its own set of keys (secrets). Putting keys on the bot does not automatically give them to the console, and the other way around.

1. What is this console?

A website for you (the owner) to manage Notbook without typing scary commands all day. You can check if things are OK, save passwords/keys, upload textbooks, talk to Render (the host), and connect the console to the bot.

Students never use this. Only you (or people you trust with the console password).

2. STATUS tab

A health checklist for this console and (when linked) the live bot.

  • TELEGRAM BOT ONLINE / OFFLINE — Can we reach the bot’s public web address? If free hosting put the bot to sleep, open the bot URL once to wake it, then refresh.
  • CONSOLE READY — Does this console have Telegram + Gemini + Pinecone keys? Needed for uploading books from the Library tab.
  • Secrets on console — Keys stored on the console service (or your PC’s .env file).
  • Secrets on bot — What we learn by asking the bot (needs link token + bot URL).
  • LOCAL PID — Only if the bot is running on the same computer as the console. On Render this is usually “no”, and that’s normal.

3. SECRETS tab

Where you type the important passwords and API keys. On your computer they save into a file called .env. On Render you should also set them under the service’s Environment page so they survive restarts.

  • TELEGRAM_BOT_TOKEN — From BotFather. Lets the bot message people on Telegram.
  • GEMINI_API_KEY — From Google. Brain for answers and for turning book text into searchable vectors.
  • PINECONE_API_KEY — From Pinecone. The online “bookshelf database” of book chunks.
  • ADMIN_USER_IDS — Your Telegram user number(s). Who’s allowed to upload books via Telegram.
  • CONSOLE_PASSWORD — Your lock on this website so strangers can’t open it.
  • RENDER_API_KEY — Optional. Lets the console press “deploy” buttons on Render for you.
  • INTERNAL_SERVICE_TOKEN — A shared password only the bot and console know, so they trust each other.
  • BOT_BASE_URL — Public link of the bot, like https://something.onrender.com.
  • CONSOLE_BASE_URL — Public link of this console.

Never put real keys into code or public chat. If a key leaks, make a new one.

4. CONFIG tab

Knobs for how the AI answers and how search works (model name, how many facts, book search settings, etc.). These write into config.yaml. You usually leave them alone unless you know what you want to tweak. Changing embeddings dimension means you must re-upload books.

5. LIBRARY tab

Upload a PDF textbook into Pinecone so the bot can study from it.

  • PDF file — The book file on your computer.
  • Display name — Friendly name people see in Telegram (Menu → Books), e.g. “Rakel”.
  • Upload progress — Bar and percent while the system reads pages, cuts text into chunks, asks Gemini to embed, then stores in Pinecone.
  • Live logs — Play-by-play text. “Namespace not found” on first upload of a book is normal (nothing to delete yet).
  • Indexed books — List of books already in the database.

After upload, in Telegram: open the bot → Menu → Books → pick the book → ask questions.

6. LINK tab

Connects console and bot when both are online (especially both on Render).

  • Save link — Stores bot URL, console URL, and the shared token.
  • Ping / pull status / books / config — Console asks the bot “are you up? what’s going on?”
  • Clear bot cache / refresh library — Console tells the bot to forget temporary memory or re-read book list.
  • Sync secrets via Render API — Pushes keys from this console’s env into the bot’s Render Environment and can redeploy (needs RENDER_API_KEY).
  • Events from bot — Notes when the bot starts or finishes something, if webhooks work.

7. RENDER tab

Talks to Render.com’s control API (needs RENDER_API_KEY).

  • List services, pick the bot, set as preferred.
  • Deploy latest code, or clear cache + deploy (full rebuild).
  • Show or pull environment variables, suspend/resume free-tier sleep.
  • View app / build logs.
  • SSH public key — only if you want shell access on paid plans; most day-to-day work uses the API key, not SSH.

8. LOCAL tab

Start/stop a bot process on the same machine as the console. On Render, leave this alone — your bot is already a separate service. Use this when developing on your laptop.

9. DEPLOY tab

Cheat sheets for hosting options (local, Docker, VPS, Render, etc.). Reminder: the Telegram bot needs a Web Service, not a Static Site. Static Site = brochure pages only; it cannot run the bot or this console’s Python server.

10. ARTIFACTS tab

Generates helper files (Docker compose, Render yaml, systemd unit, etc.) into a folder on the machine. Handy if you host outside Render later.

11. How the bot answers (super short)

  1. You ask a question in Telegram.
  2. The bot searches book chunks in Pinecone (optionally only the book you selected).
  3. Gemini writes a short, structured answer from those chunks only.
  4. You can page through details, quiz, save bookmarks, make flashcards.

12. Common “why is it broken?” moments

  • Console says missing secrets but bot works — Keys are only on the bot service. Copy them to the console Environment too (for Library upload).
  • Bot shows offline here but Telegram works — Free tier may be waking up; open the bot URL, wait, refresh Status. Or BOT_BASE_URL is wrong.
  • Upload stuck / fails — Need Gemini + Pinecone on the console; big PDFs take time; first module load can look frozen (watch live logs / heartbeats).
  • Namespace not found while clearing — First time that book name is used. Harmless.
  • API key leaked — Make new keys, put only in Environment / .env, never in code.
  • Build failed on pydantic / Python 3.14 — Use Python 3.11 (runtime.txt already pins this).

13. Safe habits

  • Always set CONSOLE_PASSWORD if the console is on the public internet.
  • Don’t screenshot or paste real keys into chats.
  • After changing keys, update both services if both need them, then redeploy if needed.
  • Prefer uploading huge textbooks from a PC (console on localhost) if cloud uploads time out.

Notbook is a study library interface, not a doctor. Answers come from your uploaded books.
