NOTBOOK CONSOLE — SIMPLE GUIDE

← Back

This console is a small control panel for you (the owner). Students never use it. It only has four jobs: status, upload books, redeploy the bot, and read logs.

Two separate apps
Bot — talks on Telegram.
Console — this website.
Each has its own Environment keys on Render. Keys on the bot do not auto-copy to the console.

1. STATUS

Quick health check. Hit REFRESH after a deploy or if something feels off.

  • TELEGRAM BOT ONLINE / OFFLINE — Can we reach the bot’s public URL? Free hosting may sleep; open the bot URL once, wait, refresh.
  • CONSOLE READY — Does this console have Gemini + Pinecone (and usually Telegram)? Needed to upload books.
  • Secrets on console / on bot — Checklist only. Change keys in the Render dashboard → Environment, not here.

If free tier slept the bot, ONLINE may say offline while Telegram still works after a wake-up.

2. LIBRARY

Put a PDF textbook into the search database so Telegram Menu → Books can use it.

  • PDF file — the book from your computer.
  • Display name — what students see (example: Rakel).
  • UPLOAD TO PINECONE — starts the job (read → chunk → embed → store).
  • Progress bar + live logs — wait until complete. Big books take a long time on free Gemini.
  • REFRESH BOOKS — list what’s already indexed.
Tips
One book at a time. Don’t re-upload while a job is still running.
“Namespace not found” on first clear is normal.
If the page glitches, check Render console logs — the job may still be running.

3. DEPLOY BOT

Tells Render to rebuild/restart the Telegram bot from the latest git code.

  • LOAD SERVICES — list your Render services (needs RENDER_API_KEY on the console Environment).
  • Bot service dropdown — pick the bot (not this console).
  • DEPLOY LATEST — normal redeploy.
  • CLEAR CACHE + DEPLOY — full rebuild (slower; use when a normal deploy acts weird).

Deploying the console does not deploy the bot, and the other way around.

4. LOGS

Read what the bot service is printing on Render.

  • First pick the bot on DEPLOY BOT.
  • APP LOGS — runtime messages (errors, answers pipeline).
  • BUILD LOGS — install / deploy build.
  • AUTO-REFRESH — reload app logs every 15 seconds.

Upload progress logs stay on the LIBRARY tab (live upload stream).

5. Where secrets live

Set keys only in Render Dashboard → each Web Service → Environment, then redeploy that service.

  • Console service: Gemini, Pinecone, Telegram (for upload), RENDER_API_KEY (for deploy/logs), BOT_BASE_URL (bot’s public URL for STATUS), CONSOLE_PASSWORD.
  • Bot service: Telegram, Gemini, Pinecone (for answering students).

6. Common problems

  • Console READY no after every deploy — keys only in a wiped disk file before; put them in Dashboard Environment.
  • Bot offline here, Telegram works — free sleep or wrong BOT_BASE_URL.
  • Upload dies / process restarts — free RAM limits on huge books; try again after Waitress deploy, one book at a time.
  • Deploy / logs buttons fail — missing RENDER_API_KEY on the console service.
  • Telegram “conflict getUpdates” — two bots using the same token (local + Render). Run only one.

Notbook is a study library from your books — not a doctor.
